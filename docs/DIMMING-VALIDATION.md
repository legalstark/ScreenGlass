# 0.7 调暗与多屏验证

本机 Windows 11，单块 1920×1080 实体屏。未声称完成双实体屏、混合 DPI、Win10、HDR、独占全屏验收。

## 执行

```powershell
# 用隔离配置验证调暗、多屏身份对应、持久化与窗口生命周期
./App/ScreenGlass.exe --dimming-test --output ./dist/dimming-final
```

专项验证包括：暗色内容固定调暗、透明度叠加及90%上限、实际显示器接口识别、两个原生遮罩不同透明度及颜色、截图排除、单屏关闭、纯调暗、总暂停、刷新定时器停止、屏幕次序改变、断开重连、设置保存与新窗口恢复。双屏场景使用两个实际原生窗口与注入的屏幕身份/区域模拟，不能替代双实体屏测试。

面板渲染位于 dist/dimming-final/main.png 和 quick.png。检查文字、滑块及快捷框滚动布局；完整工作台新增内容在主页滚动区域内。

## 内存

使用同一个独立测量程序顺序加载修改前后的 Release 程序，各阶段运行4秒；配置、屏幕、静音和窗口状态一致。使用正常系统内存计数，没有调用工作集裁剪或强制 GC。

| 场景 | 旧版工作集 MiB | 新版工作集 MiB | 旧版私有 MiB | 新版私有 MiB |
| --- | ---: | ---: | ---: | ---: |
| 面板可见，暂停 | 145.5 | 146.0 | 91.2 | 77.0 |
| 托盘，固定柔光 | 146.3 | 146.2 | 91.1 | 76.8 |
| 托盘，智能柔光 | 148.1 | 147.3 | 92.2 | 77.7 |
| 托盘，再次暂停 | 148.1 | 147.3 | 92.2 | 77.1 |

私有内存降低约16%，托管分配约由7.8 MiB降至4.1 MiB，总工作集未显著下降。结果是短时单屏测量，不是长期峰值或所有机器的保证。原始记录位于 dist/dimming-verification/memory-before.txt 和 memory-after.txt。最后增加“纯调暗”选项后未重复整套内存基准，主要窗口机制未变。

## 设计边界

- 本次是软件遮罩调暗，不包含 Twinkle Tray 的 DDC/CI 硬件控制。
- 软件调暗无法把纯黑像素变得更黑，LCD背光保持原值。
- 显示器按设备接口路径识别；更换接线端口可能产生新身份。
- 微暖为独立每屏选项；深夜场景现在只选择柔光强度。
- 无法排除采样时明确提示并停用该屏智能部分，固定调暗仍可使用。

参考产品行为：SaveMyEyes（https://github.com/KDSPL/SaveMyEyes）和 Twinkle Tray（https://github.com/xanderfrangos/twinkle-tray）。没有复制其实现代码或增加新包。
